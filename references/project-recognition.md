# 项目识别

## 可信来源顺序

1. 仓库 README、Installation/Getting Started、Security 和 `AGENTS.md`。
2. README 引用的官方 docs、部署说明和配置说明。
3. 官方部署文件、配置样例和包管理清单。
4. 版本选择需要的 Release 和迁移说明。
5. 兼容性不明确时由维护者回复的 Issue 或 Discussion。
6. 文档与实际行为冲突时的相关源码。
7. 第三方资料只作为辅助证据。

默认不要读取所有层级。

## 第一轮读取范围

读取 README、安装说明，以及其中链接的必要官方 docs。仅在存在且与识别有关时读取：

- `compose.yaml`、`docker-compose.yml` 或等价文件；
- Dockerfile；
- `.env.example`、配置样例和 `.gitignore`；
- 包管理清单；
- README 明确提到的服务或安装器定义。

特别留意 Configuration、Security、Production、Authentication、First Run、Default Credentials、Environment Variables 等章节。

只有直接读取无法获得核心文件时才临时克隆。临时副本只用于分析：不安装依赖、不构建、不拉取镜像、不运行项目代码、不修改目标环境。分析后删除，除非用户将其选为正式目录。

## 项目分类

- **可运行项目**：需要在目标设备运行的应用、服务、守护进程、CLI、网站或开发工具。
- **可导入项目**：官方路径是安装或导入，而不是服务器部署的浏览器扩展、MCP、Skill、插件、模板、库或其他制品。

Dockerfile 或 Compose 只是证据。只有官方推荐 Docker，或它明显是最简单且受支持的稳定路径时才优先 Docker。

对于浏览器扩展、MCP、Skill、插件、模板和 CLI，只按仓库证据路由到官方入口，不编造通用教程。

## 使用目标与资源

官方同时提供直接使用和开发者方式时，先确认用户目标。默认推荐满足目标且依赖较少、操作稳定、风险较低的官方路径。

- 官方给出最低或推荐配置时采用官方说明。
- 官方没有说明时，根据服务数量、数据库、浏览器和 AI 依赖做轻量判断。
- 只报告轻量、中等或较重，并说明主要原因。
- 用户选择 VPS 后，以 `preflight.sh basic` 的实际结果替代初步估算。

## 敏感配置检查

识别环境变量、API 凭据、账号密码、私钥、默认凭据、调试模式、测试配置、生产域名和付费服务。出现任一信号时读取 `secret-safety.md`。

只报告风险类型、变量名和证据位置。不要输出 `.env` 值、示例中的真实可用凭据或用户环境中的现有值。

## 第一轮回复

简洁返回：

- 项目是做什么的；
- 项目类型；
- 官方推荐方式；
- 主要依赖；
- 轻量资源判断；
- 敏感配置风险：未发现明确要求、存在待配置项或尚未确认；
- 初步建议；
- 当前决策节点必需的 1～3 个问题。

到此停止。在用户确认继续前，不创建部署记录。

## 升级证据来源

只有以下情况才读取 Release、Issue、源码或第三方说明：

- 官方文件互相矛盾或缺少必要信息；
- 目标架构或版本兼容性不明确；
- 当前证据无法解释已经观察到的错误；
- 必须理解一键脚本生成配置或处理凭据的实际行为。
