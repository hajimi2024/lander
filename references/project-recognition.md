# 项目识别

## 可信来源顺序

1. 仓库 README、Installation/Getting Started、Security 和 `AGENTS.md`。
2. README 引用的官方 docs、部署说明和配置说明。
3. 官方部署文件、配置样例和包管理清单。
4. 必要的 Release、镜像发布工作流、迁移说明、维护者回复和相关源码。
5. 第三方资料只作为辅助证据。

默认不要读取所有层级。

## 第一轮读取范围

读取 README、安装说明，以及其中链接的必要官方 docs。按需检查 Compose、Dockerfile、`.env.example`、配置样例、`.gitignore`、包管理清单和 README 明确提到的服务或安装器定义。

特别留意 Configuration、Security、Production、Authentication、First Run、Default Credentials、Environment Variables、Maintenance Status 和 Upgrade/Migration 等章节。

只有直接读取无法获得核心文件时才临时克隆。临时副本只用于分析：不安装依赖、不构建、不拉取镜像、不运行项目代码、不修改目标环境。分析后删除，除非用户将其选为正式目录。

## 项目分类

- **可运行项目**：需要在目标设备运行的应用、服务、守护进程、CLI、网站或开发工具。
- **可导入项目**：官方路径是安装或导入，而不是服务器部署的浏览器扩展、MCP、Skill、插件、模板、库或其他制品。

Dockerfile 或 Compose 只是证据。只有官方推荐 Docker，或它明显是最简单且受支持的稳定路径时才优先 Docker。

对于浏览器扩展、MCP、Skill、插件、模板和 CLI，只按仓库证据路由到官方入口，不编造通用教程。

## 任务路径

先根据用户目标选择仅分析、直接使用 Release、安装或导入、本机运行、远程部署、开发构建，或“证据不足，暂时无法确定”。不要把 GitHub 仓库自动等同于服务器部署。

官方同时提供直接使用和开发者方式时，先确认用户目标。默认推荐满足目标且依赖较少、操作稳定、风险较低的官方路径。

## 复杂度与风险

分别判断任务复杂度和操作风险，不使用文件数量、语言数量或代码规模机械评分。

复杂度信号包括多组件、多种可行路线、源码构建、数据迁移、分阶段启动，以及文档、版本或架构证据冲突。

风险信号包括秘密或默认凭据、公网或生产数据、高权限和现有服务共存、可能产生费用的外部服务，以及覆盖配置、修改防火墙、证书或 DNS 等难恢复操作。

选择执行深度：

- **轻量**：单组件、官方路径清楚、依赖少且没有明确风险信号。
- **标准**：存在配置、少量依赖、持久化或需要分阶段启动，但范围清楚。
- **增强**：出现多组件、多路线、远程公网、生产、高权限、付费服务、迁移或证据冲突。

大型仓库有可靠的直接使用入口时可以保持轻量。简单项目只要出现风险信号，就加载对应安全规则，但不添加与任务无关的检查。

## 可维护性与生产支持

- 记录仓库是否明确标注停止维护、实验性、仅供个人使用或不建议生产。
- 区分“代码可以运行”“官方仍支持部署”和“已经达到生产门槛”，三者不能互相替代。
- 检查最新稳定 Release、最近维护时间、升级或迁移入口，以及官方镜像是否仍可获取。
- README、Compose 注释和源码行为冲突时，以可执行文件和必要源码核验真实行为，并明确报告冲突。
- 停止维护或缺少关键生产路径不一定阻止隔离试运行，但必须降低成功结论，不得宣布生产就绪。

## 资源判断

- 官方给出最低或推荐配置时采用官方说明。
- 官方没有说明时，根据服务数量、数据库、浏览器和 AI 依赖做轻量判断。
- 只报告轻量、中等或较重，并说明主要原因。
- 用户选择 VPS 后，以 `preflight.sh basic` 的实际结果替代初步估算。

## 敏感配置检查

识别环境变量、API 凭据、账号密码、私钥、默认凭据、调试模式、测试配置、生产域名和付费服务。出现任一信号时读取 `secret-safety.md`。

只报告风险类型、变量名和证据位置。不要输出 `.env` 值、示例中的真实可用凭据或用户环境中的现有值。

## 第一轮回复

所有项目简洁返回项目用途和类型、用户目标和任务路径、官方推荐方式、主要依赖、资源判断、敏感配置风险、初步建议和当前必需的 1～3 个问题。

根据执行深度增加：

- 标准或增强流程列出真正影响判断的官方资料及其结论；
- 只有存在多种可行官方路线时才说明取舍；
- 只有多组件项目才列出组件、作用、依赖、内部入口、公网入口和验证方式；
- 只有网络、公网、有状态或生产任务才讨论端口、TLS、持久化、备份等对应事项。

到此停止。在用户确认继续前，不创建部署记录。

## 升级证据来源

只有以下情况才读取 Release、Issue、源码或第三方说明：

- 官方文件互相矛盾或缺少必要信息；
- 目标架构或版本兼容性不明确；
- Release tag、容器 tag、包版本或发布渠道的对应关系不明确；
- 当前证据无法解释已经观察到的错误；
- 必须理解一键脚本生成配置或处理凭据的实际行为。
