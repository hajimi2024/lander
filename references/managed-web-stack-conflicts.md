# 既有 Web 栈共存

只有检测到既有 Web 面板、反向代理、证书续签体系、80/443 端口占用，或用户明确说明服务器已有站点/入口时才加载。

## 常见候选标记

```text
/etc/nginx
/etc/caddy
/etc/apache2
/etc/traefik
/opt
/srv
/var/www
/www/wwwroot
/home/web
/root/.acme.sh
/etc/letsencrypt
```

这些路径只表示需要进一步确认，不是默认部署目标。通过站点配置、Compose、证书目录和定时任务判断已有服务，不假定面板目录或证书路径。

## 安全共存

- 修改环境前运行 `preflight.sh web-stack`。
- 检查宿主机和容器中的 Nginx、Caddy、Traefik、Apache、HAProxy，以及 80/443 端口归属。
- 选择唯一权威入口，不让宿主机代理、容器代理、面板代理和新应用争用同一公网端口。
- 独立应用放在用户确认的部署根目录，不默认绑定到面板目录。
- 将上游绑定到 loopback 或私有 Docker 网络，只添加必需的站点配置。
- 修改前备份相关配置，修改后验证现有站点仍可访问。

## 证书与续签

- 不先删除现有证书、证书目录、全局续签任务、cron 或 systemd timer。
- 新域名优先采用 `security-and-access.md` 中的 DNS-01 方案。
- 必须使用 HTTP-01 时，先确认当前 80 端口的权威入口，只修改目标域名。
- 安装证书后只 reload 当前权威入口，不重启无关容器。
- 先切换一个站点，完成访问、续签和 reload 验证，再停用已被替代的旧任务。

## 排查升级

1. 记录代理、证书工具、定时任务和站点配置基线。
2. 检查实际生效的代理和 Compose 配置。
3. 对照已安装面板或代理工具的官方文档。
4. 修改前确认命令是否会停止 80/443 的现有服务。

不要通过大范围停止容器、关闭防火墙、清空代理配置或替换整套证书体系解决单个应用接入问题。
