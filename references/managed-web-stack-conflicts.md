# 既有 Web 栈共存

只有检测到既有 Web 面板、反向代理、证书续签体系、80/443 端口占用，或用户明确说明服务器已有站点/入口时，才加载本文件。

## 常见标记与目录

将以下路径视为“需要进一步确认”的候选标记，不要把它们当成默认部署目标：

```text
/etc/nginx
/etc/caddy
/etc/apache2
/etc/traefik
/opt
/srv
/var/www
/www/wwwroot
/home/web
/root/.acme.sh
/etc/letsencrypt
```

通过 `wp-config.php`、`wp-content`、站点配置文件、Compose 文件、证书目录和定时任务判断已有服务。不要假定域名目录、面板目录或证书路径。

## 安全共存

- 修改环境前运行 `preflight.sh web-stack`。
- 同时检查宿主机和容器中的 Nginx、Caddy、Traefik、Apache、HAProxy，以及 80/443 端口归属。
- 选择唯一权威入口。不要让宿主机代理、容器代理、面板代理或新应用代理争用同一公网端口。
- 独立 GitHub 应用默认放在用户确认的部署根目录，例如 `/opt/docker-apps/<project>`；不要绑定到某个面板目录，除非用户明确选择该面板集成。
- 将上游应用绑定到 loopback 或私有 Docker 网络，只向权威入口添加必需的站点配置。
- 修改前备份受影响的站点配置，修改后验证现有站点仍可访问。

## 证书与续签

- 不要先删除现有证书、证书目录、全局续签任务、cron 或 systemd timer。
- 新接入且 DNS 托管支持 API 的域名，优先采用 `security-and-access.md` 中的 DNS-01 方案，避免为了申请证书停止现有入口或抢占 80 端口。
- 如果必须使用 HTTP-01，先确认当前 80 端口的权威入口，并采用只影响目标域名的临时配置。
- 安装证书后，只 reload 当前权威入口；不要重启无关容器或全局代理。
- 先切换一个站点，完成外部访问验证、续签 dry-run 或等价检查、reload 验证，再停用该域名已经被替代的旧任务。

## 排查升级

生成行为不清楚或反复修复失败时：

1. 记录当前代理、证书工具、定时任务和站点配置的基线。
2. 检查实际生效的 Compose、Nginx/Caddy/Traefik/Apache/HAProxy 配置。
3. 对照已安装面板或代理工具的官方文档，不盲目重新运行一键脚本或初始化命令。
4. 修改前确认该命令是否会停止占用 80/443 的容器、进程或现有站点。

不要通过大范围停止容器、关闭防火墙、清空代理配置或替换整套证书体系来解决单个应用的接入问题。
