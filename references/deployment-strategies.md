# 执行策略

遵循具体仓库的官方说明，不把本文件当作安装百科。

## 可运行与可导入

- **可运行项目**：选择运行位置和官方运行方式，然后配置、启动并验证。
- **可导入项目**：遵循官方安装或导入入口，不强行套用 Docker 或 VPS。

根据证据路由浏览器扩展、MCP、Skill、插件、模板、库和 CLI。只有实际使用证明某类项目需要大量独立规则时，才拆分专用模块。

## 自适应深度

- **轻量流程**：确认目标和官方入口后，完成一个必要操作、最小验证和简短交接。不创建路线表、组件拓扑或部署记录。
- **标准流程**：增加相关环境预检、配置检查、阶段执行、验证和维护说明。
- **增强流程**：增加关键资料回执、路线取舍、组件关系、安全门、逐组件验证和部署记录。

默认从轻量流程开始。只有项目证据或操作风险要求时升级；后续证据表明任务更简单时可以收敛。安全规则独立判断，不因流程轻量而省略。

## 方法选择

1. 确认用户目标是直接使用还是开发源码。
2. 在官方方式中选择依赖较少、操作稳定、风险较低且满足目标的路径。
3. 长期运行时采用官方生产建议。
4. 只有目标环境限制要求时才使用官方支持的替代方式。

简单使用路径已经满足目标时，不默认进入 `npm install`、开发服务器或构建流程。

官方推荐并提供受支持运行环境、持久化和更新路径时选择 Docker/Compose。项目需要宿主机集成或容器化会变成不受支持的重新设计时，选择原生安装。

只有两种以上官方路线都能满足目标时才比较方案。说明选中路线及未选路线的关键原因，不为明显不适用的方式制作长表格。

## 目标设备

- **本地电脑**：使用原生平台或受支持的容器运行时；除非用户明确要求，不处理公网入口和证书。
- **WSL2**：按 Linux 环境处理，同时考虑 Windows 文件系统、端口、服务和重启边界。
- **VPS**：任何修改前运行 `preflight.sh basic`；仅按路线增加 `docker`、`ingress` 或 `web-stack`。

## 配置与秘密信息

发现敏感配置时读取 `secret-safety.md`。区分：

- 普通配置：端口、语言、功能开关等可以公开的值；
- 秘密信息：Token、密码、私钥、Cookie Secret 和完整连接字符串；
- 生产门槛：默认凭据、调试模式、认证、域名、TLS、持久化和备份。

只确认当前阶段必需的设置。真实秘密由用户在目标环境的受限位置填写。

## Docker/Compose 顺序

启动前：

- 验证 Compose 配置能够解析；
- 确认镜像版本、端口归属和网络；
- 通过官方 registry、manifest、实际 pull 或发布工作流核验完整镜像引用；不要从 Git tag 或 Release 名机械推导容器 tag，拉取后记录 digest；
- 检查 bind mount 路径、目录所有权和写入权限；
- 覆盖镜像内的数据或配置目录前，确认镜像是否预置数据库、默认配置或初始化文件；空 bind mount 可能遮蔽这些内容，应按官方方式预填目录或使用会复制初始内容的 named volume；
- 明确持久化卷、备份范围和秘密注入方式；
- 确认数据库建表、迁移、首次管理员和其他初始化步骤在所选生产模式下真实执行；不要为了触发初始化而长期启用调试模式；
- 确认不会覆盖或停止无关服务。

启动后：

- 检查容器状态、健康检查和必要日志；
- 验证本地上游或应用响应；
- 对有状态服务执行一次无敏感数据的最小写入和读取，并在重启后复查，验证挂载、迁移和持久化真实生效；
- 再测试用户选择的外部访问方式。

## 通用执行原则

- 记录 Release、tag、commit 或镜像标识。
- 在首次修改前说明目标、影响和撤销方式；备份会被覆盖的配置，并使用可恢复的覆盖方式。
- 将秘密排除在版本控制、命令参数、日志和输出之外。
- 明确所有权、重启行为和更新方式。
- 轻量任务可以一次完成单一官方操作；其他任务每次执行一个阶段，验证后再继续。

## 路线验证

- **Release 或直接使用**：文件完整、版本正确、能够启动并完成一个最小功能。
- **CLI 或原生安装**：命令可发现、版本正确、最小命令成功，并说明移除方式。
- **Skill、MCP、扩展或其他导入项目**：目标 Agent 或应用能够识别，并完成最小调用或功能检查。
- **本地应用**：进程、必要端口、应用响应和退出方式；只有存在状态数据时才验证持久化。
- **Docker/Compose**：配置有效性、容器、网络、端口、挂载、健康和适用的资源限制。
- **VPS 网络服务**：先验证本地上游，再验证反向代理、外部访问、HTTPS 和重要现有服务。
- **开发构建**：只验证用户要求的构建、测试或开发入口，不把开发环境宣布为生产可用。

只验证当前路线应有的结果，不用 Web 服务标准验收 CLI、导入项目或简单本地工具。

验证命令必须来自项目文档、OpenAPI/Swagger、CLI 帮助、源码路由或实际响应。先确认状态码、字段和数据粒度，再编写断言；一个接口返回成功不等于后续读取使用常见字段名就一定正确。出现不一致时先修正验证探针，再判断应用故障。

## 交接深度

- 轻量任务说明安装位置、版本、使用方式、验证结果和移除方法。
- 标准任务增加配置位置、启动停止、持久化和更新方式。
- 增强任务增加组件关系、访问入口、安全状态、备份恢复和剩余风险。

所有任务都在对话中输出交接简报。只有实际部署或长期运行任务才创建私有部署报告。

## 失败处理

失败时保留准确错误和基线状态。按文档/版本、镜像引用、架构、依赖、初始化/迁移、认证、网络、端口、存储、权限、验证探针、运行时或应用行为分类，不掩盖失败进入后续阶段。
