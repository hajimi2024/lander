# 部署记录约定

只有满足生命周期条件时才创建记录。默认不要将运行记录存入 Skill 或上游 Repository。

## 默认位置

```text
$CODEX_HOME/deployment-records/<owner>--<repo>/<target>/
```

使用稳定且不含秘密信息的目标标签，例如 `local-windows`、`wsl-debian` 或用户确认的服务器别名。不要包含密码、Token 或完整连接字符串。

除非用户要求远程留档，否则不要将记录同步到远程目标。

## 公开发布与导出

部署记录属于本地私有运维资料。不得自动将其加入 Git 暂存区、提交、PR、Issue、Release、CI 制品或任何公开上传内容。

如果用户明确要求公开分享部署资料：

1. 保留本地私有原件，另行生成公开副本，不要覆盖原件。
2. 再次脱敏目标 IP、主机名、账号标识、域名、内部路径、非必要端口、私有服务名、访问命令和秘密存放位置；必要时使用概括性描述替代。
3. 删除所有密码、API Key、Token、Cookie、SSH Key、`.env` 内容、登录状态及可用于推断秘密的信息。
4. 在执行 `git add`、`git commit`、`git push` 或上传前，检查待提交文件与差异；发现部署记录原件、秘密文件或未脱敏内容时，停止发布并排除它们。
5. 用户要求将项目发布到 GitHub，不等于授权发布部署记录或目标环境信息；两者必须分开处理。

## PROJECT_SUMMARY.md

满足以下条件后创建：

1. 第一轮项目识别回复已经完成；
2. 用户确认继续落地项目。

使用 `assets/templates/project-summary.md`。选定版本、项目分类、官方方式或建议发生实质变化时更新。

## DEPLOYMENT_LOG.md

第一次修改状态前立即创建。使用 `assets/templates/deployment-log.md`，并简要补记已经完成的项目识别、目标预检和方案确认等关键节点。

只追加有意义的事件：

- 已确认环境适配性；
- 部署或配置阶段开始/完成；
- 验证通过/失败；
- 稳定暂停、更新、迁移或回滚。

不要记录终端流水、原始日志、秘密信息、Cookie、完整环境变量值或私钥。

## DEPLOYMENT_REPORT.md

成功落地，或任务在可恢复的稳定节点正式暂停时创建或更新。使用 `assets/templates/deployment-report.md`。将其维护为当前运维状态快照，而不是事件历史。

## 回滚

只有真正发生回滚时才创建 `ROLLBACK_REPORT.md`。根据实际事件生成，不维护空白模板。

## 编辑规则

- 优先记录简洁事实，不写冗长叙述。
- 已知时区时，使用包含时区的 ISO 格式日期。
- 只记录秘密信息的保存位置，不记录值。
- 只在适用时记录或链接仓库、版本、目标、目录、端口、访问方式、数据持久化、状态、运维方式、风险和下一步。
