# 交接与部署记录约定

所有任务都要在对话中提供交接简报。只有标准或增强流程中的实际服务部署、长期运行或需要持续维护的任务才创建文件记录。默认不要将运行记录存入 Skill 或上游仓库。

Release 下载、CLI 安装、Skill/MCP/扩展导入和一次性本机验证，即使创建或修改了临时文件，也不创建 `PROJECT_SUMMARY.md`、`DEPLOYMENT_LOG.md` 或 `DEPLOYMENT_REPORT.md`；用户明确要求留档时例外。

## 对话交接简报

任务成功、部分成功、阻塞或回滚时都要输出，状态只使用：

```text
成功 / 部分成功 / 阻塞 / 已回滚
```

始终说明采用路线和精确版本或镜像 digest、验证结果及使用方式。项目停止维护、实验性或不建议生产时说明上游状态。区分已经验证的范围、未验证的范围和因外部条件阻塞的范围，不把部分闭环写成全面成功。环境修改、撤销方式、剩余风险、安装位置、端口、组件、访问入口、持久化、备份和证书等内容仅在适用时出现。

关键结果没有完成验证时，不得报告成功。无法安全创建文件记录时，说明原因并完整输出对话交接。

## 默认位置

```text
$CODEX_HOME/deployment-records/<owner>--<repo>/<target>/
```

目标标签不得包含密码、Token、完整连接字符串、IP 或域名。除非用户要求远程留档，否则不要将记录同步到目标服务器。

## 公开发布与导出

部署记录属于本地私有运维资料，不得自动加入 Git 暂存区、提交、PR、Issue、Release、CI 制品或公开上传。

用户明确要求公开分享时：

1. 保留私有原件，另行生成公开副本。
2. 脱敏 IP、主机名、账号、域名、内部路径、非必要端口、私有服务名、访问命令和秘密存放位置。
3. 删除密码、API Key、Token、Cookie、SSH Key、`.env` 内容、登录状态和可用于推断秘密的信息。
4. 在 `git add`、`git commit`、`git push` 或上传前检查文件和差异。
5. 发布项目到 GitHub 不等于授权发布部署记录。

## PROJECT_SUMMARY.md

标准或增强流程中的实际服务部署、长期运行任务在第一轮识别完成且用户确认继续后创建。使用 `assets/templates/project-summary.md`。版本、分类、执行深度、官方方式、敏感配置风险或生产要求发生变化时更新。

轻量安装、导入、CLI 和一次性本地任务不创建该文件。

## DEPLOYMENT_LOG.md

标准或增强流程中的实际服务部署、长期运行任务在第一次修改状态前创建。使用 `assets/templates/deployment-log.md`，只追加有意义的事件：

- 环境适配性已确认；
- 敏感配置已提醒、已确认或需轮换；
- 部署或配置阶段开始/完成；
- 验证通过/失败；
- 稳定暂停、更新、迁移或回滚。

不要记录终端流水、原始日志、秘密值、Cookie、完整环境变量或私钥。

## DEPLOYMENT_REPORT.md

标准或增强流程中的实际服务部署、长期运行任务成功落地，或在可恢复的稳定节点正式暂停时创建或更新。使用 `assets/templates/deployment-report.md`，维护当前状态而不是事件历史。简单安装、导入和本地工具只提供对话交接简报。

秘密信息只记录：

- 保存位置；
- 权限是否已限制；
- 默认凭据是否已处理；
- 是否完成验证；
- 轮换责任和待办。

不得记录真实值。

报告按任务适用性填写字段。无关字段直接删除，不要用大量“不适用”填充。

## 回滚与编辑

- 只有真正发生回滚时才创建 `ROLLBACK_REPORT.md`。
- 优先记录简洁事实。
- 已知时区时使用包含时区的 ISO 日期。
- 公开副本不记录秘密存放位置。
