# 脚本与面板项目交接

仅在项目提供安装脚本、管理命令、交互菜单、后台面板、首次管理员或容器内运维入口时加载。目标是让用户能够接手，不改写上游脚本，也不输出完整菜单翻译。

## 核实管理入口

从官方文档、安装结果、服务定义或容器内实际命令确认：

- 管理入口运行在宿主机、容器、Compose 服务还是平台控制台；
- 面板路径、监听地址和外部访问方式；
- 账号是项目默认、安装器生成、Agent 重置还是用户提供；
- 数据、配置、日志和证书由什么组件管理。

交付的命令必须匹配真实部署方式。容器部署使用经过验证的 `docker exec` 或 Compose 命令，不假设宿主机存在同名快捷命令。

## 登录信息

在对话交接中说明：

- 面板、前台和 API 等适用的访问入口；
- HTTPS 状态和必要的非默认路径；
- 用户名；
- 凭据来源、处理状态、保存位置和轮换待办。

默认凭据在公网开放前完成替换或禁用。隐藏路径和非标准端口只能减少扫描噪声，不能代替身份验证。

明文密码不得写入 README、普通 Markdown 报告、Issue、PR 或 Git。需要保存时使用平台 Secret 或目标主机受限文件；Linux root 部署可使用 `/root/lander-credentials/<project>.env` 并设置 `600`。

用户明确要求在当前私密对话中取得临时测试密码时，可以单次提供，标明来源并提醒正式使用前轮换。数据库只保存哈希时只能走官方重置流程，不承诺找回明文。

## 中文管理速查

只列已经验证且用户接手最需要的命令，通常包括启动/停止、重启、状态、日志、更新和账号重置。卸载、清空数据、修改防火墙、证书切换和数据库迁移等高影响命令只说明用途，不在未确认影响时执行。

每项使用独立的两行：第一行是 inline code 命令，第二行是中文说明。不要把多个命令合并到带注释的代码块，也不要把说明放在命令前。

格式：

```markdown
`docker restart <container>`
重启项目容器。
```

完成标准：逐项交代访问入口、HTTPS、用户名、凭据来源、默认凭据处理状态、保存位置、文件权限和真实管理命令；未知项明确写“尚未确认”，不静默省略。交接文件中没有明文秘密。
