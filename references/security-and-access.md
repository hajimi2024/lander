# 安全与访问

仅在网络服务需要选择或配置访问方式时加载。发现凭据时同时应用 `references/secret-safety.md`。

## 选择访问方式

只提供适用选项：

- **SSH 本地端口转发**：临时私有访问，应用绑定 loopback。
- **公网 IP 和端口**：直接暴露，需确认防火墙、认证和默认凭据。
- **域名和 HTTPS 反向代理**：长期运行的公网服务。
- **Cloudflare Tunnel**：使用域名但不直接发布应用端口。

选择标准是用户范围、持续时间、认证能力和现有入口，不默认把服务开放到公网。

## 公网入口

修改前运行 `scripts/preflight.sh ingress`，确认 80/443 归属并复用唯一权威入口。

- 上游绑定 loopback 或私有容器网络；
- 备份目标站点配置，配置校验通过后再 reload；
- 只在应用需要时增加 WebSocket、上传大小和超时；
- 管理后台优先限制来源、增加独立认证或保持私有；
- 隐藏路径和非标准端口不能代替身份验证。

扫描、截图、抓取、文件转换、构建或 AI 推理等高消耗功能还要确认目标范围、内网/元数据访问边界、并发和限流。缺少应用保护时，在反向代理增加认证或保持私有。

## TLS 与续签

使用现有证书体系时保持唯一责任方。DNS 托管在 Cloudflare 且用户能提供目标 Zone 的受限 Token 时，可选择 `acme.sh + DNS-01`，避免占用 80 端口并支持通配符证书。

只申请实际需要的域名，将完整证书链和私钥安装到权威入口，限制私钥权限，并验证 reload hook。不要先删除现有证书或续签任务；先完成单站点切换、外部访问、续签和 reload 验证，再停用被替代任务。

## 外部服务

涉及支付、邮件、短信、DNS、对象存储、AI 或其他外部 API 时，确认测试/生产环境、最小权限、额度、费用和滥用风险。使用无敏感数据的最小请求验证，不因技术验证发布真实业务数据。

完成标准：用户选择的访问范围可用，公网入口、认证、TLS 和续签责任均已验证或明确标为待办。
