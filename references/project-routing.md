# 项目路由

每次任务先读取本文件。完成分类后回到 `SKILL.md` 选择一个主要路线，不继续浏览无关文档。

## 最小资料扫描

先读取 README、安装或快速开始章节，以及 README 指向的必要官方 docs。按目标检查配置样例、包管理清单、Release、Compose、Dockerfile 或安装器定义；只读取能够改变路线判断的文件。

特别留意 Configuration、Security、Production、Authentication、First Run、Default Credentials、Environment Variables、Maintenance Status、Upgrade 和 Migration。

直接读取不足时，可以克隆到用户临时目录或系统临时目录下的独立子目录。这是首轮唯一允许的受限写入：只做搜索和读取，不安装、不构建、不运行代码，也不作为正式部署目录。记录所创建的准确路径；除非用户明确将其选为正式目录，分析完成后删除该子目录。

## 分类顺序

1. **用户目标**：仅分析、直接使用、安装或导入、本机运行、远程部署，还是开发构建。
2. **项目类型**：便携制品、CLI、可导入制品、单体服务、多组件服务，或证据不足。
3. **官方入口**：Release、包管理器、安装脚本、原生运行、Docker/Compose 或目标应用内导入。
4. **执行深度**：轻量、标准或增强。
5. **风险信号**：秘密、默认凭据、付费权限、公网、生产、高权限、数据迁移或现有服务冲突。

Dockerfile 和 Compose 只是证据。官方同时提供直接使用和开发方式时，默认选择满足目标的直接使用入口。

## 深度判断

- **轻量**：单一官方入口、依赖少、操作范围小。
- **标准**：需要配置、持久化、少量依赖或分阶段启动。
- **增强**：多组件、多条可行路线、远程公网、生产、高权限、迁移、付费服务或证据冲突。

不要使用文件数量、语言数量或代码规模机械评分。大型仓库有可靠的一键入口时仍可轻量；简单项目出现风险信号时保留轻量主路线并叠加对应安全分支。

## 首轮输出

简洁说明：

- 项目类型与用途；
- 用户目标；
- 官方入口与建议的主要路线；
- 执行深度；
- 已发现的风险类型及证据位置；
- 当前必需的 0～3 个问题；证据足够时不为形式而提问。

只有多条路线都能满足目标时才比较取舍，只有多组件项目才列组件关系。到此停止，不执行、不创建部署记录。

完成标准：已获得足够证据选择一个主要路线，或明确报告缺少什么证据而暂时停止。

## 证据升级

仅在以下情况读取 Release、Issue、必要源码或第三方资料：

- 官方文件互相矛盾或缺少关键步骤；
- 版本、镜像、架构或发布渠道对应关系不明；
- 项目维护状态影响目标；
- 当前证据无法解释观察到的错误；
- 必须理解安装脚本生成配置、凭据或管理入口的真实行为。
