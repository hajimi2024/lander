# 敏感配置与生产安全

仅在项目出现秘密、默认凭据、付费权限或生产配置时加载。只检查实际信号，不向普通 CLI 和无状态导入任务追加服务器问题。

## 识别

从官方资料、`.env.example`、Compose 和配置样例识别：

- API Key、Token、密码、数据库连接、Webhook Secret 和签名密钥；
- SSH/TLS 私钥、Cookie Secret、OAuth Client Secret 和云服务凭据；
- 默认管理员、初始密码、首次登录和无需认证的管理入口；
- 调试模式、测试配置、示例凭据和宽松访问设置；
- AI、支付、邮件、短信、DNS、对象存储等外部服务及费用风险。

只报告名称、用途、是否必填和证据位置。没有足够证据时写“尚未确认”，不读取或显示真实值。

## 配置交接

进入配置阶段前说明每项秘密的名称、用途、官方来源、建议保存位置、最小权限和当前状态。状态使用“待填写 / 已填写 / 已验证 / 需轮换”。

- 让用户在目标终端、受限文件或平台 Secret 管理界面填写真实值。
- 避免秘密进入对话、命令参数、Shell 历史、进程列表、日志和渲染后的 Compose 配置。
- `.env` 不是加密存储；限制权限并确认已排除版本控制。
- 不在 Dockerfile 的 `ARG` 或 `ENV` 固化生产秘密。
- Token 使用目标资源范围内的最小权限；能限制有效期、额度或来源时使用限制。

## 默认凭据与初始化

区分固定默认凭据、安装器随机生成凭据和首次初始化流程。

- 初始化接口先保持在 loopback、SSH 隧道或其他受限入口；
- 随机凭据保存到受限位置，只报告位置、权限和状态；
- 公网开放前更换、禁用或确认默认凭据已经失效；
- 只存哈希时使用官方重置流程，不尝试还原明文；
- 验证旧凭据失效时不复述新旧值。

## 生产门

宣布生产就绪前确认：

- 使用官方生产启动方式，调试模式已关闭；
- 域名、监听地址、Allowed Hosts、CORS 和回调地址符合实际范围；
- HTTPS、安全 Cookie、会话密钥和管理入口保护已启用；
- 数据库、上传和其他状态数据已持久化并具备备份路径；
- 测试账号、示例凭据和开发数据已移除或隔离；
- 外部 API 的环境、最小权限、额度、费用和轮换方式已确认。

未确认的项目写入剩余风险，不宣布生产就绪。

## 验证与泄露响应

只验证变量已加载、文件权限合理和最小功能成功，不打印值。检查日志、错误页和部署记录没有秘密。

用户误发秘密时不复述、不保存，并提醒撤销或轮换。怀疑秘密进入 Git 历史、CI 制品或公开位置时，先轮换，再清理暴露内容。

完成标准：当前阶段必需的秘密均有安全的填写位置和明确状态；默认凭据、公网门槛和轮换待办没有被遗漏。
