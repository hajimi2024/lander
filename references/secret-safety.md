# 敏感配置与生产安全

发现环境变量、凭据、默认账号或生产配置时加载本文件。

## 安全覆盖规则

安全风险与项目复杂度分开判断。即使任务采用轻量流程，只要出现秘密、默认凭据、付费权限、公网入口、生产数据或高权限操作，就执行本文件中对应的检查。

只检查实际出现的风险，不向普通 CLI、本地工具或无状态导入任务追加无关的服务器安全问题。状态统一写为“通过”“阻塞”“不适用”或“尚未确认”；相同风险只在状态变化或进入关键门槛时再次提醒。

## 识别范围

从 README、官方 docs、安装说明、`.env.example`、Compose、Dockerfile 和配置样例中识别：

- API Key、Token、密码、数据库连接、Webhook Secret 和签名密钥；
- SSH 私钥、TLS 私钥、Cookie Secret、OAuth Client Secret 和云服务凭据；
- 默认管理员、初始密码、首次登录和无需认证的管理入口；
- `DEBUG`、测试模式、开发服务器、示例凭据和宽松访问设置；
- AI、支付、邮件、短信、DNS、对象存储等外部服务及其费用风险。

只报告变量名、用途、是否必填和证据位置。不要读取、显示或复制真实值。没有足够证据时写“尚未确认”，不要写“无风险”。

## 配置清单

进入配置阶段前，向用户列出：

| 项目 | 要求 |
|---|---|
| 名称 | 环境变量或配置项名称 |
| 用途 | 该值控制的服务或权限 |
| 来源 | 官方文档或配置样例位置 |
| 保存位置 | 目标终端、受限文件或平台 Secret 管理界面 |
| 权限 | 满足任务所需的最小权限 |
| 状态 | 待填写、已填写、已验证或需轮换 |

不要在表格中加入真实值。

## 填写与保存

- 不要求用户把秘密粘贴到对话、Issue、PR、截图或部署报告中。
- 避免通过命令参数、Shell 历史、进程列表、调试输出和渲染后的 Compose 配置暴露秘密。
- 使用项目官方支持的秘密注入方式。没有专用 Secret 管理时，使用受限文件并排除版本控制。
- `.env` 是配置载体，不等同于加密的秘密管理系统。限制文件权限并确认 `.gitignore`。
- 不在 Dockerfile 的 `ARG` 或 `ENV` 中固化生产秘密；优先使用运行时注入、Compose secrets 或平台 Secret。
- Token 只授予目标资源和当前任务需要的权限；能设置有效期、额度或来源限制时使用限制。

## 默认凭据与首次初始化

- 分别标记固定默认凭据、随机生成的初始凭据和首次初始化流程；不要把“尚未设置密码”误报成项目附带默认密码。
- 发现默认账号、初始密码、首次登录密钥或无需认证的初始化接口时，明确标记。
- 本机隔离试运行可以保留到首次登录步骤，但必须提醒更换。
- 首次初始化接口只能在 loopback、SSH 隧道、临时来源限制或其他私有入口下完成；初始化成功并确认不能重复执行后，才开放公网。
- 随机生成的凭据保存在受限位置，只报告保存位置、权限和处理状态，不在日志或交接中显示值。
- 开放局域网、公网或宣布生产就绪前，必须更换、禁用或确认默认凭据已经失效。
- 验证时检查旧凭据不再可用，但不要在输出中复述新旧值。

## 开发到生产

切换生产环境前确认：

- 调试模式关闭，使用官方生产启动方式；
- 域名、监听地址、Allowed Hosts、CORS 和 OAuth 回调符合实际范围；
- HTTPS、安全 Cookie、会话密钥和管理入口保护已启用；
- 数据库、上传目录和其他状态数据已经持久化并具备备份路径；
- 测试账号、示例凭据和开发数据已移除或隔离；
- 外部 API 已确认测试/生产环境、最小权限、额度、费用和轮换方式。

任何一项未确认时，报告为待办，不要宣布生产就绪。

## 验证与泄露响应

- 只验证变量存在、权限合理、应用成功加载和最小功能可用，不打印值。
- 检查日志、错误页和部署记录中没有秘密。
- 用户在对话中发送秘密时，不复述、不保存；提醒立即撤销或轮换。
- 怀疑秘密进入 Git 历史、CI 制品或公开位置时，先轮换，再按对应平台流程清理暴露内容。
